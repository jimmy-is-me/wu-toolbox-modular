# IndexNow 自動通知與發布健檢

WU Toolbox Modular 4.2.6 · SEO Core 1.5.0

## 正式站操作

1. 進入 **Wu Toolbox → WU SEO 視覺化儀表板 → IndexNow → 設定與測試**。先確認 Yoast、Rank Math 或 Cloudflare 的 IndexNow 設定，每個網站只指定一個整合發送。
2. 在「驗證檔」產生金鑰，或填入既有金鑰。留空自訂網址時，WordPress 會提供站點根路徑（子目錄站點為站點目錄）的金鑰文字檔。點「驗證公開檔案」，確認匿名 GET 直接回傳 HTTP 200，內容與金鑰完全相符。
3. 在「自動通知」勾選啟用，選擇文章、頁面及其他公開類型並儲存。啟用時會再檢查一次公開驗證檔。現有內容不會整批回送。
4. 於「測試提交」輸入一條近期變更的正式公開網址，排入背景提交。重新整理後切到「查看全部狀態」，查看這筆 URL 的回應。到 **Bing Webmaster Tools → 選擇已驗證網站 → IndexNow** 核對提交。
5. 如需停止，關閉自動通知。佇列和既有紀錄保留。更換金鑰或檔案位置時，請重新驗證並啟用。

## 驗證檔與多站點

- 若預設路徑被重寫、快取、維護頁或 WAF 攔截，查看實際 HTTP、回應型態、轉址及快取標頭。可以將金鑰寫進網站可公開存取的 UTF-8 文字檔，檔案內容僅有金鑰，無 BOM 或換行。在自訂驗證檔網址填入同來源的完整 `.txt` 網址。子資料夾內的檔案只驗證該目錄範圍。
- 多站點的設定、資料表、排程及統計各站保存；每站各自驗證。同一主機下的子目錄站只會提交該站目錄內的正式網址。搬站後請在新網址重新驗證。
- 若 WordPress 外送 HTTP 無法讀取本站，但外部訪客可讀，請先修正從主機到公開網址的連線。驗證必須實際成功。自動通知由 WP-Cron 執行，正式站若將 WP-Cron 改由主機排程觸發，請維持該排程運作。

## 通知與健檢結果

- 通知涵蓋首次公開、排程發布、實質修改、改址、下架和刪除，以及原可索引網址的 noindex／canonical 變更。草稿、自動儲存、修訂、未更改的儲存及系統欄位不會提交。相同網址的待處理變更會合併。
- 新增與更新用正式公開網址。若網頁無法確認為正常公開的原網址，會留在後台供管理者檢查。舊網址、下架及索引條件變更的通知可繼續送出。健康檢查分開記錄公開 HTTP、頁面及標頭 robots、canonical 和公開 Sitemap。
- 子 Sitemap 檢查使用現有 WordPress 原生索引，依內容類型分批讀取，每次檢查最多 30 個候選子檔。找不到及異常時顯示已讀範圍；可能受快取影響的結果會延後複查。修正後也可手動重跑。
- HTTP 200 表示已送達。202 表示已接收，等待金鑰驗證。429 依 Retry-After 延後整站該佇列；網路及 5xx 會有限次退避重試。API 回應與檢查時間可於各列「詳情」查看。已結束的工作保留 90 天。
- 提交圖表計算實際要求中的網址數，包含重試。發布健檢只表示 WordPress 及匿名 HTTP 的觀測結果。索引狀態請分別到 Bing Webmaster Tools 或 Google Search Console 查詢。
