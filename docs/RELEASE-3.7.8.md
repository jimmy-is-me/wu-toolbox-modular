# v3.7.8 — Invoice dependency isolation

- Confirmed the reported `GuzzleHttp\describe_type()` line-41 fatal with a real foreign Composer Guzzle 7 install. The old Guzzle 6 function loader guards a function absent in Guzzle 7 and then redeclares shared functions. A runtime Throwable boundary cannot repair this compile error.
- Both invoice runtimes now use private `WUTMInvoiceDeps` namespaces for Guzzle, Promises, PSR-7/interfaces, InvoicePorter, ODS Metabox and Symfony polyfills. The ECPay SDK uses `WUTMInvoiceSDK_`, including dynamic method factories and class guards. No aliases or replacements of other plugins' classes/functions are installed. Package versions and licenses remain unchanged.
- Private IDN normalization no longer depends on a global Normalizer class or mb_chr. Remove InvoicePorter's global exception-handler replacement: WordPress and other plugins retain their own error handling.
- Settings IDs, checkout fields, order meta, issue/update/void request builders and provider endpoints are preserved. Explicit source-preservation checks distinguish namespace/guard adapters from the two intentionally revised admin scripts. Blocks/HPOS support is not newly certified.
- Manual order AJAX operations receive a local Throwable boundary with sanitized location-only logs and an uncertainty warning. Admin scripts unblock on HTTP/JSON failure, suppress concurrent submissions, use current-version cache keys and declare jquery-blockui. Never automatically retry a potentially completed financial operation; check the provider portal first.
- Regression tests use pinned real Guzzle 7 / PSR 2 in both loading orders, foreign SDK/metabox symbols, private and foreign mock HTTP requests, invoice encryption roundtrip, ECPay signed dynamic factory selection, original source/permission tests and browser payload/error/double-click checks. All external invoice transports are mocked; no real invoices are issued or voided.
- Tutor Pro itself and the customer's authenticated production environment are not available locally. Real dependency coexistence is tested, but production installation and merchant-side issue/void/reconciliation still require a test merchant account. Namespace isolation does not upgrade the historical provider protocol or its bundled dependency versions.

## Dependency maintenance

`tests/scope-invoice-dependencies.php` performs the deterministic namespace/SDK token transformation; rerunning on shipped sources must change zero files. Four upstream truncated SDK class guards were corrected to the actual private names. The private IDN fallback and removal of the global exception-handler override are intentional local patches, not package upgrades. Keep all vendor license/attribution files. The pinned foreign Composer fixture is test-only and excluded from release ZIPs.
