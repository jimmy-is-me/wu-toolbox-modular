# WU 藍新金流／物流／EZPAY 電子發票工具

位置：電商第三方金物流 → 綠界工具後方。設定入口為 WU Toolbox 子選單。

## 設定順序

1. 開啟模組卡片。新藍新金物流服務預設關閉，測試環境預設開啟；舊 EZPAY 卡片曾啟用的網站會沿用卡片狀態，但不會啟用新的付款服務。
2. 「藍新金流」填入商店 MerchantID、32 字元 HashKey、16 字元 HashIV，可設定訂單前綴與分期獨立顯示。
3. 「服務開關」開啟藍新金流；至 WooCommerce 付款設定分別啟用信用卡、分期（3／6／12／18／24／30 期）、WebATM、ATM、超商代碼或條碼。實際可用方式仍取決於商店合約與個別付款設定。
4. 如需藍新超商取貨，開啟物流並於 WooCommerce 運送區域加入藍新超商取貨；設定費用、免運條件、重量及運費類別。不得強制配送至帳單地址。取貨門市在藍新付款流程選擇；不是綠界的獨立選店地圖，也不提供來源未實作的宅配／列印託運單功能。
5. 「EZPAY 電子發票」沿用原測試／正式商店設定、個人／公司／捐贈、載具、手動／自動開立與作廢、訂單欄位及會員查詢。新網站發票服務預設關閉；舊網站已儲存的發票開關與訂單資料保留。已啟用綠界電子發票時，WU 會暫停 EZPAY 執行；可繼續使用綠界金物流。

## 相容性與維護

- PHP 8.0+、OpenSSL、WooCommerce；支援傳統結帳及傳統訂單儲存。本合併模組目前不宣告完整區塊結帳／HPOS 發票介面相容；請先完成測試站驗證，不直接在正式站切換儲存或結帳模式。
- 新金物流類別、設定、付款／物流 ID、通知網址、樣式與腳本均使用 WU 識別，不接管其他金物流外掛的資料。舊外掛的待付款訂單仍由原外掛處理。
- EZPAY 的歷史設定／訂單鍵刻意保留，不因品牌命名改變而搬遷。發票依賴仍使用隔離命名空間，避免與 Tutor Pro 等外掛的 Guzzle 衝突。來源授權與版權保留於 NOTICE／LICENSE，不作介面宣傳。
- 付款通知驗證 TradeSha、商店、金額、TWD、已建立的訂單交易與付款／取貨方式；已付款的不同交易不可覆蓋原交易。重複通知不再次觸發付款事件，並使用資料庫原子鎖防止同時處理。
- EZPAY 同訂單開立／作廢共用操作鎖；已開立的訂單不重複呼叫開立。網路錯誤不會自動重送；請先在服務商後台確認，避免因回應不明而重複操作。
- 新增藍新商店設定不會自動退款、同步舊訂單、建立物流單或開立發票。服務商付款、超取及發票 API 為不同服務，請勿混用金鑰。

## 上線驗證

測試商店先驗證成功／失敗付款、ATM／超商待繳資訊、分期、重複通知、超商取貨及貨到付款，再驗證 EZPAY 個人／公司／捐贈與開立／作廢。自動測試只使用模擬回應及測試資料，不能取代商家合約、正式通知可達性與實際對帳確認。
