# v3.7.4 — Legible modal thumbnails and manual full-library reading

- Main media-dialog grids now size columns from the actual grid viewport after reserving folder/sidebar space. Scoped grid child widths override stale native data-columns widths; the native attachment view's columns stay aligned for keyboard navigation. Resize observation includes grid hosts, so sidebar/layout changes recalculate without polling. upload.php and the bottom selection strip are not restyled.
- Media Encoder adds an explicit, read-only “手動讀取全庫檔案” action over WordPress attachment records, including video/PDF and other non-image media. It does not crawl arbitrary filesystem directories or auto-start on opening the page.
- Reuse the nonce/capability-protected 20-record keyset endpoint. No COUNT, OFFSET, unbounded query or background task. Client requests are serial with a delay and 20-second round budget; users can stop/resume, and failures preserve successful counters/cursors. Invalid/non-decreasing cursors stop safely.
- Accumulate counters only; keep the first/current pages, not the entire library in memory/DOM. The table remains paginated, with page-local search/filter/conversion. Partial statistics are labelled incomplete. WebP percentage uses image records only; bytes/count include all readable attachments. Results reflect this read sequence, not an atomic snapshot of a changing library.
- Non-images are read only. Server conversion now checks both registered media type and actual image format; existing JPEG/PNG conversion safeguards, backups, retention, settings and upload behavior remain intact.
- Tests include 24 realistic thumbnail elements with stale data-columns, desktop/mobile/sidebar cases, full-library pagination, stop/resume, failure retry, invalid cursors, no duplicate counts, no automatic conversions/polling, bounded SQL and existing GD conversion regressions.
