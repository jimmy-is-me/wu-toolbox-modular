# 頁面快取與網站速度（v3.5.5）

WU Toolbox 的頁面快取只處理可公開共享的完整 HTML。登入、購物車、結帳、會員、搜尋、預覽、REST、帶查詢參數等動態請求都略過。TranslatePress 公開翻譯頁（例如 `/en/`）支援快取：網址、語言與裝置分別建立版本。若曾手動加入 `/en/` 免快取，請移除該行再清除快取；自訂排除不會被外掛擅自刪除。

快取以 GZIP 儲存在磁碟上，但在 PHP 命中時解壓並輸出 HTML。這避免輸出緩衝修改位元組後與預設的 `Content-Length` 不符。Nginx 或 Cloudflare 負責傳輸 GZIP；不要再由 PHP 重複壓縮。同一頁依桌面、平板、手機分開快取，內容更新與外掛更新會清除相關或全部快取。

參考 xSpeed 的速度功能時，本站應避免疊加功能造成重複處理：

| 項目 | 採用方式 |
| --- | --- |
| 頁面快取 | 本模組快取完整、公開且翻譯完成後的 HTML；動態頁略過。 |
| HTML／CSS／JS 壓縮 | 不在頁面快取中重寫輸出。主題、外掛或既有資產流程若已壓縮，重複壓縮可能破壞程式碼或增加 CPU。 |
| GZIP | 磁碟快取使用 GZIP；網路回應沿用 Nginx／Cloudflare 的壓縮。 |
| 圖片／iframe 延遲載入 | 沿用 WordPress 原生 `loading` 規則及既有圖片模組，不對首屏圖片強制 lazy load。影片維持既有頁面設定。 |
| 瀏覽器快取 | 靜態圖片、CSS、JS 的期限應由 Nginx／Cloudflare 設定；PHP 的 HTML 快取無法替靜態檔案設定回應標頭。 |
| 字型最佳化 | 只預載確定用於首屏的字型；避免全站自動預載造成競爭下載。`font-display` 應在實際字型 CSS 中設定。 |

## 使用與驗證

1. 更新並開啟頁面快取模組。管理列「頁面快取」直接進入設定頁；子選單可清除快取。首次進入後台會移除舊格式檔案，既有 TTL、自動清除與免快取設定保留。
2. 用全新的無痕視窗、不登入、不加入購物車，開啟原始語言或 `/en/` 等翻譯公開頁面。網址不要有查詢參數（`?`）。
3. 同一裝置開啟同一網址兩次。在瀏覽器網路面板檢查文件回應：第一次 `X-WUTM-Page-Cache: MISS`、第二次 `HIT`。`MISS` 表示開始嘗試，不保證最終可寫入；若持續 MISS 請看運作診斷。
4. 被排除的匿名請求回應 `BYPASS` 與 `X-WUTM-Cache-Reason`。TranslatePress 公開翻譯頁應先 MISS 再 HIT；翻譯編輯器帶查詢參數，仍不快取；登入、後台及 AJAX 不採樣。
5. 回到設定頁重新整理，總覽顯示「有效快取版本」與最近 100 個檔案。桌面、平板、手機是不同版本，數字不是瀏覽人次。過期檔案分開計數，下一次瀏覽該頁會重新建立。

## 為何訪客瀏覽後沒有資料？

舊版在 `shutdown` 讀取目前最上層輸出緩衝。如果佈景主題、WordPress 或外掛開了另一層空白／轉換緩衝，讀到的就不是完整文件，或緩衝已提前輸出。v3.5.4 由快取自身的輸出處理器接收內層完成後的 HTML，不再盲讀其他緩衝。已用本機 HTTP 重現並驗證；仍須在實際網站確認環境條件。

| 診斷結果 | 處理方式 |
| --- | --- |
| `cache-created`／`cache-hit` | 已建立／命中快取。 |
| `private-cookie` | 新的無痕視窗再測；登入、工作階段、WooCommerce／EDD 購物車 Cookie 不共用快取。不要關閉保護來強迫寫入。 |
| `private-response`／`do-not-cache` | 其他外掛禁止快取、設定 Cookie、自訂壓縮／長度或非 HTML；先確認該頁是否真的適合公開共用。 |
| `excluded-path`／`commerce-page` | 正常排除。翻譯頁若仍被排除，檢查是否曾手動加入 `/en/`；保留購物車、結帳、會員中心的保護。 |
| `directory-or-lock`／`write-error` | 檢查目錄權限、可用磁碟空間；清理鎖定時前台不等待，可稍後再測。不要把整個 wp-content 設成 777。 |
| `streamed-output`／`incomplete-html`／`large-output` | 串流、清空或不完整文件不快取；超過 4 MB 略過，以限制記憶體。頁面仍原樣輸出。 |
| 完全沒有 WU 標頭與診斷 | 確認模組啟用；CDN、伺服器或其他全頁快取可能在 WordPress 執行前已回應，WU 無法記錄未經本模組的請求。 |

診斷只保留一筆匿名原因抽樣，每 30 秒至多更新一次；不是即時紀錄，也不記錄 IP、網址或 Cookie 值。第一筆排除原因可能維持至下一次抽樣。最近建立檔案仍可從清單確認。

## 效能與安全界線

- 沒有新增前台 CSS／JS、輪詢、預熱排程或逐次資料庫寫入；設定頁 CSS 僅在此模組後台載入，沒有持續動畫。
- 前台只讀取對應裝置快取；統計掃描與目錄寫入測試只在有管理權限的設定頁執行。最近清單最多保留 100 筆，輸出緩衝與解壓上限 4 MB。
- 鎖定忙碌時前台直接略過，不等清理。完整寫入後才替換檔案；內容更新或清除會更新世代標記，避免正在產生的舊頁面在清除後寫回。
- 登入、驗證標頭、Cookie、敏感頁面、禁止快取標頭、依 Cookie／驗證／語言變動的 Vary 回應、非 200、致命錯誤和不完整 HTML 仍排除；不會為了增加數字而快取個人化資料。
- 不啟用 WordPress `WP_CACHE`／advanced-cache drop-in，命中仍經過 WordPress 啟動；此模組主要省下模板與內容產生工作，不保證零成本或固定速度提升。
- 若網站同時使用其他全頁快取，請避免同一 HTML 疊加不同規則。網路壓縮沿用既有 PHP／主機／CDN 壓縮設定，本模組不設定壓縮回應的固定 Content-Length。
## 翻譯內容與快取更新

- TranslatePress 在 `init` 啟動翻譯輸出緩衝；本模組在它之前建立有大小上限的外層緩衝，於翻譯與內層輸出完成後才保存。不是保存中文模板再套用英文網址。命中時透過官方 `trp_stop_translating_page` 避免再次解析已翻譯 HTML。
- 預設「內容更新時自動清除」開啟時，TranslatePress 一般／gettext 翻譯儲存、語言設定更新與 WU AI 批次／CSV 字典寫入均會清除快取。外部程式直接修改資料庫、其他翻譯匯入工具，請完成後手動清除；停用自動清除時亦應手動清除或等 TTL 到期。
- `translation-buffer-unavailable` 表示翻譯外層緩衝曾被提前清空／輸出，會安全略過保存，不會改變頁面內容。
- 請分別用無痕視窗打開中文與英文頁面兩次，確認第二次 HIT、語言正確且購物車／結帳仍 BYPASS；主機/CDN 全頁快取若先回應，WU 不會記錄該次請求。

已使用 TranslatePress 官方公開套件的輸出流程與鉤子核對，並以本機 HTTP 重現先翻譯後快取、HIT 不重複翻譯及語言隔離。實際網站仍需更新後確認伺服器、外部快取與自訂排除規則。
