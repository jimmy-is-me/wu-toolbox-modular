# SEO 管理與技術診斷（4.0.1）

入口：Wu Toolbox → SEO 管理與診斷。SEO 核心卡片與既有全站設定入口保留。

## Sitemap 擷取異常時

1. 按「檢查 Sitemap 索引並預覽」。使用 WordPress 原生動態網址，包含子目錄、純查詢式固定網址與子網站。
2. 從 HTML 預覽逐一檢查子 Sitemap。索引可讀不代表子檔可讀，沒有檢查的子檔不會顯示成功。
3. 核對 HTTP 200、XML Content-Type、UTF-8、Namespace、網址、重複項目及 lastmod。HTTP 403、驗證挑戰、轉址循環或 HTML 錯誤頁會明確回報。
4. 如有 403／挑戰，請用檢查時間與網址比對主機／防火牆紀錄，確認公開爬蟲存取；不要改分數來掩蓋。一般伺服器請求不是 Googlebot 驗證。
5. 在 Search Console 的 Sitemap 報表提交 XML，並針對內容頁使用網址檢查。Sitemap 本身不需要出現在搜尋結果；提交成功也不保證內容收錄。

預設 XML 不附 XSLT。可手動選擇 XSLT 美化，或保留 XML 並在管理介面看獨立 HTML 預覽。停用瀏覽器 XSLT 不影響原生 XML 資料。

每次只檢查選取的 Sitemap；最多 5 次轉址、每請求 8 秒、回應最多 2 MB、快取 5 分鐘。超出診斷容量會顯示尚未完整驗證，而非判定 XML 無效。只允許目前網域及同名 www 形式，搭配 WordPress 安全 HTTP 防護；不攜帶登入 Cookie。網站網址檢查另抽樣最多 3 個內部連結。

保留原生公開內容／分類提供者，排除 noindex、非公開、密碼保護及指向其他網址的 Canonical。無 HTTP 請求在 Sitemap 生成流程執行。Canonical 排除清單以 250 筆分頁建立、快取 5 分鐘；自訂轉址外掛可用 `wu_seo_redirected_post_ids` 提供本機轉址 ID，避免逐頁連線查轉址。第三方外掛的未知轉址仍需按需診斷確認。

robots.txt 只讀、不覆蓋實體檔案；檢查 Sitemap 宣告、根路徑封鎖、無效 Noindex 指令及 WordPress 公開設定。子目錄站另確認網域根目錄是否由主機提供實體檔案。複雜 User-agent 規則仍需人工核對。

## 列表、快速編輯與歷史

公開且可編輯的文章、頁面、商品、自訂文章類型會提供 SEO 欄位。使用原生「顯示項目設定」控制顯示。狀態區分手動／範本／noindex；自動範本不是錯誤。

原生快速編輯支援標題、摘要、主題、Canonical、noindex、nofollow；「SEO 快速編輯」面板另有社群欄位、搜尋／社群預覽與最近修改歷史。圖片以媒體 ID 指定。每篇保留最近 50 個欄位修改，記錄人員、時間與前後值；還原只改選取的 SEO 欄位，不改正文。透過核心 metadata API 的編輯器修改亦會記錄。

批次每次最多 50 筆，僅修改指定欄位，預設只補空白。已有明確 0 的 robots 設定會保留。先產生修改前預覽，再勾選確認套用；預覽限目前使用者、10 分鐘有效且只能使用一次。其他人修改資料後會略過該筆，顯示原因，需重新預覽。

CSV 匯出每批 50 筆，可依頁碼分批下載。匯入最多 1 MB／50 筆，可設定來源欄名與 SEO 欄名對應（如 `編號=id,標題=title`）。只使用已存在且目前帳號可編輯的內容 ID；不新增文章或修改正文。匯出針對試算表公式字首加保護，附格式標記以便安全回匯。

## 內容分析與通用設定

內容分析由管理員逐批啟動，每批 50 篇，需按順序續掃，進度保留 1 小時。累計自訂／範本／noindex／摘要缺漏、重複標題、描述與 Canonical，完成後列出「正文無入站內連的候選頁」。選單、短碼、動態區塊、JavaScript 及頁面編輯器可能另有內容與連結，候選頁不直接判為孤立頁。實際 HTML 可用網址檢查，沒有驗證的部分會明確標記。

語系與地區不再限制台灣；Schema／Open Graph 使用目前語系。網站可選擇不提供組織 Schema，或填寫真實組織、線上商店、實體商家資料。實體商家資料不足時退回 Organization；不產生假地址、價格、評價。WooCommerce 自己的 Product 資料仍由 WooCommerce 負責。公開 CPT 預設 WebPage，可用 `wu_seo_schema_type` 擴充真實內容類型。

保留既有設定鍵、SEO metadata 與舊資料，不進行破壞性搬移。既有設定未填組織類型時沿用原本 Organization 行為；新站預設不假設是組織。其他主流 SEO 外掛擁有輸出時，本模組不接管 Meta、Schema 或 Sitemap。

多語系的語言版本、hreflang、翻譯後 Canonical 與 Sitemap 由既有多語系提供者維護，不另外拼接語言路徑。網址診斷會呈現實際 hreflang 與 Canonical，仍需在各語言驗證。

## Google Search Console（選用）

在 Google Cloud 啟用 Search Console API，建立 Web OAuth 用戶端，將設定頁顯示的 callback URL 加入允許的重新導向網址。輸入用戶端 ID、密鑰及 Search Console 資源，使用自己的 Google 帳號授權唯讀存取。

按需讀取近 28 天與前 28 天的熱門查詢／頁面、點擊、曝光、CTR、平均排名；各前 25 筆，快取 15 分鐘，非全站總計。沒有授權時不影響核心功能，且不會顯示虛構外部數據。搜尋成效不代表即時索引或 Googlebot 存取。

需要 OpenSSL。密鑰與更新權杖以目前網站 salt、子網站 ID 及網址衍生的金鑰加密儲存，不載入前台，不寫入修改歷史。搬站或更換 salt 後需重新設定及授權；可移除本機授權，也可至 Google 帳戶撤銷存取。

## 驗證界線

自動回歸涵蓋 XML 安全、原生文章／公開 CPT／分類 Sitemap、noindex／Canonical／密碼與草稿排除、metadata 權限與歷史、批次並行保護、HTTP 錯誤與挑戰、子目錄／純查詢式網址、OAuth 加密、多站設定／快取／憑證隔離，以及四種寬度的編輯介面。原有傳統編輯器與 Gutenberg metadata 註冊流程保留。

真正 Google 帳號的 OAuth 同意及資料、實際 Googlebot、各主機／CDN 的公開存取，以及每一款多語系外掛的翻譯路徑，必須在個別網站驗證；本次不把模擬測試當成這些服務已實測通過。網站既有 PHP／主機／防火牆造成的 403 也不會因更新程式就被宣稱已解除。
