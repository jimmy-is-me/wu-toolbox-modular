# v3.7.5 — Media safety cleaner module

- Adapt the supplied WUMETAX Media Cleaner v2.2.0 as a new, disabled-by-default `media-safe-cleaner` module in 媒體工具, with the existing Toolbox sharing/card/settings and submenu ordering mechanisms. No external plugin dependency; no frontend hooks/assets or scheduled cleanup.
- Preserve all reference features: date-based year/month index, date/filename/title/path/MIME filters (JPEG, PNG, WebP, GIF, AVIF, HEIC/HEIF), optional parent exclusion, 15,000-result ceiling, 48-row pagination, grid/list preference, mirrored selection, select-clean, original/edit links, CSV BOM/formula protection, per-user one-hour token snapshot, typed/double confirmation, selected/all 20-item deletion batches, pause, progress, protection/failed/leftover logs. Year/month grouping is upload date, not a physical filesystem crawl.
- Keep all original reference protection checks (site icon/logo/theme image, featured image, shared registered original file, content and supported builders). Add supported-builder URL/path patterns and WooCommerce product-gallery protection. DB reference-query errors fail closed. Native per-post capabilities and current filters are checked again before deletion.
- Restrict native permanent deletion to validated local uploads paths, including metadata originals, sizes, original-image and backup filenames; reject traversal, remote paths and resolved paths/symlinks outside uploads. No arbitrary file deletion or recursive directory sweep is introduced. Use `wp_delete_attachment` to remove registered originals/thumbnails and report leftover originals.
- Isolate PHP class, action, transient and browser configuration names from the standalone reference. Keep own page-hook-scoped assets, common Toolbox presentation root/header and mobile overflow containment. UI result notes use escaped text; blocked localStorage cannot disable the interface; network timeout stops automatic continuation.
- Reference detection is conservative but cannot prove an image unused: external pages, custom dynamic code, unknown plugin/options data, transformed filenames and offloaded files require manual review. Back up database/uploads first. Permanent deletion is not reversible; the module never runs it automatically.
- Tests: retained methods/features, bounded prepared filtering, permissions/nonces/snapshot ownership/confirmation, out-of-preview IDs, changed filters, DB errors, unsafe original/thumbnail/backup paths, native deletion delegation, frontend isolation, four browser widths, grid/list selection and confirmations. Disposable CI WordPress additionally verifies real reference SQL and native original/registered-thumbnail removal. No customer-site media is deleted during tests.
