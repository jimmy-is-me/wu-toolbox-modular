# v3.7.6 — Invoice modules and category shortcuts

- Add EZPAY 電子發票 and 綠界電子發票 cards under 電商電子發票 immediately after 電商支付工具. Both are opt-in, require WooCommerce and PHP 8+, and retain the supplied source's settings, order data, API/SDKs, classic checkout fields, carrier/donation/company options, manual/automatic issuing/voiding, order columns/metaboxes, member account display and dependencies/licenses.
- Source: https://github.com/jimmy-is-me/invoice at `081dc3aad9d39dec8cd9f638ec6ad071a0833883` (standalone 1.0.1). Runtime source is preserved; bootstrap is adapted to the Toolbox lifecycle and cached settings-page object. Settings IDs and API payloads/order metadata are not renamed. Vendor demo entry points gain direct-access guards, not runtime changes.
- Toolbox submenus render the original complete field definitions through WooCommerce's field output/save handlers, with shared presentation, capability checks and a dedicated nonce. Native WooCommerce settings tabs remain compatible. No migration overwrites stored credentials/order data; no automatic switch to production or automatic activation.
- Refuse enabling a second invoice module; fail closed at runtime if both flags were externally enabled, a same/upstream/other standalone invoice plugin is loaded, or the existing official ECPay integration's invoice option is enabled. Do not change or disable existing payments/logistics/options. AJAX mutations gain a preflight nonce, order existence and WooCommerce management/edit capability check before original handlers execute. Existing services must be deliberately disabled by the administrator before migration.
- Add a single-row, horizontally scrollable quick category navigation below dashboard search, generated from the actual permitted/rendered groups. Native anchors, keyboard focus and reduced-motion behavior are retained. Links follow enabled/disabled filter visibility; shared administrators only receive links for their shared categories. No hard-coded category inventory.
- Tests exercise source bootstrap/dependencies/field IDs, enabled/disabled/missing-WooCommerce/upstream/official/both-provider conflict states, mutation preflight, cached settings, category order/link targets, shared-view isolation and desktop/mobile navigation alongside the full regression suite.
- No real invoice is issued/voided or customer account contacted by tests. Source support for block checkout and complete HPOS operation was not certified upstream; this release makes no new compatibility claim. Validate real issuing/voiding with your provider's test merchant account before production. Duplicate/timeout reconciliation still requires provider-side confirmation; conflict checks are not an assertion of universal exactly-once invoice delivery.
