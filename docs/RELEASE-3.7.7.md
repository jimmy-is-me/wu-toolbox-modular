# v3.7.7 — Dashboard environment compatibility and recoverable rendering

- Reproduced a fatal owner-resolution path with ctype_digit disabled and an explicitly stored owner list. Replace it with equivalent anchored ASCII-digit validation using preg_match, retaining owner filtering and capabilities. No new owners or universal administrator access are inferred.
- Isolate optional license-status, third-party activation-status and license-panel errors. Preflight plugin statuses before emitting controls. When status cannot be trusted, retain cards/settings links but lock module toggles and omit sharing controls. No activation, license reset, option rewrite or role changes occur on page load. An isolated license panel error discards partial panel markup while retaining the dashboard.
- Add a dashboard-only Throwable boundary with balanced output buffers and a minimal retry view. Silent authorization returns now explain no-access, without exposing cards or granting access. WordPress routing/capabilities are not bypassed.
- Diagnostic references, never raw exceptions/credentials, are shown. Server error_log receives only reference, version, stage, exception class, source basename and line; no messages, arguments, full paths, customer data or license keys. References are request-local; no diagnostic database option is created.
- Tests cover missing/disabled ctype, selected/legacy/recovery owners, role/share isolation, injected optional failures, partial panel disposal, read-only degradation, privacy, buffer balance and normal behavior. Existing browser/mobile and module checks remain enabled.
- The affected customer's authenticated browser/PHP logs were unavailable. The reproducible ctype and silent/uncaught renderer paths are corrected, but ctype is not confirmed as that site's root cause and the installed site has not been directly verified. If the issue persists, the new reference can locate failing code without resetting settings. Startup/parse/memory-exhaustion failures outside the renderer still require host logs.
